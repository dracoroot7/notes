# Style, Presentation & Formatting Guidelines

## Style & Presentation
- **Clarity first**: Explain concepts clearly before diving into technical details.
- **Code & Math examples required**: Include working, tested code snippets and LaTeX math formulas (`$...$` / `$$...$$`) where applicable.
- **Markdown format**: All notes use GitHub-flavored markdown with consistent structure.
- **Practical focus**: Prioritize real-world use cases, interactive roadmaps, and reference guides over theoretical background.

## Content Structure & Formatting
- **Headings**: Use markdown headings for organization (`h2` for major sections, `h3` for subsections).
- **Relative URIs**: Always use relative URIs/paths for internal cross-references (e.g., `[Title](filename.md)` instead of absolute `file:///` paths).
- **Learning Roadmaps**: Use interactive markdown checklists (`- [ ]`) and phased badges (`🟢 Phase 1`, `🟡 Phase 2`) for structured learning plans.
- **Code Blocks**: Include appropriate language syntax highlighting with bash/shell examples ready for copy-pasting.
- **Mathematical Expressions**: Use standard LaTeX syntax (`$inline$` or `$$block$$`) for math (logarithms, matrices, statistics).
